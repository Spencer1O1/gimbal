This project is a programming language built genuinely around category theory.

Its central thesis is:

> Programs are typed morphisms, and composition is the primary means by which programs are constructed.

The language combines:

- **Conceptual simplicity:** a small number of deep mechanisms with minimal overlap.
- **Strong safety:** compile-time guarantees and explicit trust or unsafe boundaries.
- **Categorical honesty:** every foundational feature must have a precise categorical meaning, laws, and connection to the existing semantics.
- **Practical execution:** the language must eventually support real programs, systems interaction, resources, concurrency, and low-level interoperability without abandoning its categorical foundation.

The project begins with a tiny total and pure categorical kernel.

Later language layers may use additional categories and structures, but they must remain connected through explicit functors, adjunctions, modalities, handlers, interpretations, or other mathematically defined constructions.

The project does not require every future feature to live inside one ordinary bicartesian closed category.

It requires every feature to enter through a coherent categorical extension rather than an unrelated compiler mechanism.

## Phase 0 Foundation

For a supplied signature `Σ`, Phase 0 constructs the syntactic presentation of the free bicartesian closed category generated by that signature.

Its object grammar is:

```text
A ::= Base(id)
    | Unit
    | Never
    | A × B
    | A + B
    | A ⇒ B
```

Its primitive morphism constructors are:

```text
id
composition
discard
absurd
first
second
pair
left
right
case
curry
eval
signature generators
```

Every core morphism has exactly one source and one target:

```text
f : A ⟶ B
```

Multiple inputs and outputs are represented using products.

A closed value of `A` is a morphism:

```text
Unit ⟶ A
```

A first-class function value inhabits an exponential object:

```text
A ⇒ B
```

A morphism:

```text
A ⟶ B
```

and a closed value:

```text
Unit ⟶ (A ⇒ B)
```

are related through currying but are not the same judgment.

## Free Bicartesian Closed Category

The central Phase 0 metatheoretic result is:

> The category of checked core morphisms modulo definitional equality is the free bicartesian closed category generated by the supplied signature.

Conceptually, for any bicartesian closed category `D` and any interpretation of the signature generators in `D`, there exists a unique structure-preserving functor:

```text
⟦-⟧ : CΣ → D
```

extending that interpretation.

This theorem establishes that the core is not merely category-inspired syntax.

Its semantics are characterized by a categorical universal property.

## Derived Structures

The core contains only the universal constructions.

Useful structures are derived from them.

For example:

```text
alias Bool = Unit + Unit
```

with:

```text
false = left[Unit, Unit]
true  = right[Unit, Unit]
```

Boolean branching is coproduct elimination.

Similarly, these structures are derived rather than primitive:

- Product and coproduct swapping
- Reassociation
- Adding or removing `Unit`
- Adding or removing `Never`
- `uncurry`
- Function application syntax
- Tuple syntax
- Pattern matching
- Records
- Variants

The compiler may optimize a derived structure only when the optimization is justified by construction, proof, or another explicit trust boundary.

## Structural Equality

Core object equality is structural.

These are distinct core objects:

```text
(A × B) × C
A × (B × C)

A × B
B × A

A × Unit
A
```

They may be connected by canonical isomorphisms, but they are not definitionally identical.

The kernel uses chosen terminal, initial, product, coproduct, and exponential structures.

Their coherence is represented through explicit morphisms and proven laws rather than silent object rearrangement.

## Signatures and Models

Phase 0 does not permanently hardcode `Nat`, `Int`, `Text`, or another data object.

A signature supplies:

- Opaque base-object identities
- Typed atomic generating morphisms

Example:

```text
base Number

generator two   : Unit ⟶ Number
generator three : Unit ⟶ Number
generator add   : Number × Number ⟶ Number
```

A categorical model of the signature consists of:

- A bicartesian closed category
- An interpretation of every base object
- An interpretation of every generator

The Phase 0 Rust interpreter is one executable model adapter.

It is not the mathematical definition of a model.

Real categorical natural numbers, lists, and trees arrive through controlled initial-algebra constructions rather than permanent compiler primitives.

## Equality

The project permanently distinguishes:

### Definitional equality

Equality generated by the trusted bicartesian-closed laws.

It is decidable in Phase 0.

### Proven equality

Additional equalities established by explicit proof evidence.

These do not silently enter definitional equality.

### Model-specific observational equality

Two morphisms may behave identically in one model without being equal in the free category.

Model-specific facts do not alter core definitional equality.

Phase 0 definitional equality is decided by a complete procedure based on saturated focusing.

Its termination, soundness, and completeness must be machine-checked in Lean 4.

The shipped Rust implementation must be connected to the verified algorithm.

## Future Semantic Layers

The pure cartesian category describes persistent pure values.

It does not automatically describe resource-sensitive values such as:

- File handles
- Sockets
- Unique memory
- Locks
- Linear capabilities

Those require a noncartesian resource-sensitive layer connected to the pure value category by explicit categorical structure.

Similarly:

- Effectful computations require a defined value/computation semantics.
- First-order algebraic effects arise from free algebraic constructions.
- Scoped and higher-order effects require principled categorical generalizations.
- Inductive data arise from initial algebras of approved strictly positive functors.
- Genuine parametric polymorphism requires richer categorical semantics and is not merely Phase 0 syntactic sugar.
- User-defined categories must distinguish external compiler declarations from internal category values.
