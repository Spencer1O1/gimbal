## 2. Signature

A signature `Σ` contains:

- A collection of base-object generators
- A collection of generating morphisms
- A source and target object expression for each generating morphism

The signature contains no equations between generators.

It therefore presents a freely generated theory subject only to the bicartesian-closed laws.

---

## 3. Raw Syntax and Checked Morphisms

The implementation distinguishes:

```text
Term
```

which may be ill typed, from:

```text
Morphism(A, B)
```

which is a checked morphism from `A` to `B`.

The Lean formalization may use intrinsically typed or extrinsically typed syntax.

Whichever representation is chosen, it must correspond precisely to the Rust kernel boundary.

---

## 4. Definitional Equality

Definitional equality is the smallest congruence containing:

- Category identity and associativity laws
- Terminal uniqueness
- Initial uniqueness
- Product beta and eta
- Coproduct beta and eta
- Exponential beta and eta

It includes all required consequences under composition and congruence.

Opaque generators have no additional equations.

---

## 5. Construction of the Syntactic Category

For each signature `Σ`, construct `CΣ`.

### Objects

Objects of `CΣ` are well-formed core objects.

### Morphisms

A morphism:

```text
A ⟶ B
```

is a checked core morphism from `A` to `B` modulo definitional equality.

### Identity

```text
id[A]
```

### Composition

```text
f >>> g
```

### Required proofs

Lean must prove:

- Definitional equality is an equivalence relation.
- Composition respects definitional equality.
- Identity respects equivalence classes.
- Composition is associative.
- Identity laws hold.
- `CΣ` is a category.

---

## 6. Terminal Object

`Unit` is the chosen terminal object.

For every object `A`, the chosen morphism is:

```text
discard[A] : A ⟶ Unit
```

Lean must prove:

- Existence of the chosen morphism
- Uniqueness of every morphism `A ⟶ Unit`

---

## 7. Initial Object

`Never` is the chosen initial object.

For every object `A`, the chosen morphism is:

```text
absurd[A] : Never ⟶ A
```

Lean must prove:

- Existence
- Uniqueness of every morphism `Never ⟶ A`

---

## 8. Products

For objects `A` and `B`, the chosen product is:

```text
A × B
```

with projections:

```text
first[A, B]  : A × B ⟶ A
second[A, B] : A × B ⟶ B
```

For:

```text
f : X ⟶ A
g : X ⟶ B
```

the chosen pairing is:

```text
pair(f, g) : X ⟶ A × B
```

Lean must prove:

- Projection equations
- Uniqueness of pairing
- The full product universal property

---

## 9. Coproducts

For objects `A` and `B`, the chosen coproduct is:

```text
A + B
```

with injections:

```text
left[A, B]  : A ⟶ A + B
right[A, B] : B ⟶ A + B
```

For:

```text
f : A ⟶ X
g : B ⟶ X
```

the chosen copairing is:

```text
case(f, g) : A + B ⟶ X
```

Lean must prove:

- Injection equations
- Uniqueness of copairing
- The full coproduct universal property

---

## 10. Exponentials

For objects `A` and `B`, the chosen exponential is:

```text
A ⇒ B
```

with evaluation:

```text
eval[A, B] : (A ⇒ B) × A ⟶ B
```

For:

```text
f : X × A ⟶ B
```

the chosen transpose is:

```text
curry(f) : X ⟶ A ⇒ B
```

Lean must prove the natural bijection:

```text
Hom(X × A, B)
≅
Hom(X, A ⇒ B)
```

including:

- Beta
- Eta
- Naturality in `X`

---

## 11. Bicartesian Closed Structure

Lean must assemble the previous results into a proof that `CΣ` is bicartesian closed with chosen structure.

The formalization must identify which laws hold:

- Definitionally in the formal representation
- Propositionally by proof
- Only after quotienting by definitional equality

---

## 12. Free Bicartesian Closed Category Theorem

Let `D` be a bicartesian closed category with chosen structure.

Let an interpretation `J` assign:

- Each base object of `Σ` to an object of `D`
- Each generator `q : A ⟶ B` to a morphism:

```text
J(q) : J(A) ⟶ J(B)
```

Then Lean must construct a functor:

```text
interpret J : CΣ ⟶ D
```

that strictly preserves:

- `Unit`
- `Never`
- Products
- Coproducts
- Exponentials
- The selected introduction and elimination morphisms

The main theorem is:

> `interpret J` is the unique strict bicartesian-closed functor extending `J`.

Required results include:

- Interpretation of objects
- Interpretation of morphisms
- Respect for definitional equality
- Preservation of identity
- Preservation of composition
- Preservation of chosen terminal structure
- Preservation of chosen initial structure
- Preservation of products
- Preservation of coproducts
- Preservation of exponentials
- Extension of generator interpretation
- Uniqueness

---

## 13. Strict Versus Strong Preservation

Phase 0 formalizes strict preservation of chosen structure.

This means the interpretation is defined so that selected syntax constructors map directly to selected target-category structure.

More general interpretations preserving structure up to coherent isomorphism may be introduced later.

Such interpretations require explicit coherence data and proofs.

They are not silently treated as strict.

---

## 14. Equality Decision Procedure

The equality decision procedure uses a typed lambda-calculus presentation with:

- Atomic types
- Unit
- Empty type
- Products
- Sums
- Functions
- Opaque typed constants

Checked categorical morphisms translate into this calculus.

The procedure then uses focusing and saturation.

Required machine-checked results:

- Translation preserves typing.
- Translation preserves categorical equality.
- Translation reflects categorical equality.
- Focusing terminates.
- Saturation terminates.
- Comparison is decidable.
- Comparison is sound.
- Comparison is complete.

---

## 15. Relationship Between Equality and the Syntactic Category

Lean must prove:

```text
decideEquality(f, g) = true
```

if and only if:

```text
[f] = [g]
```

as morphisms in `CΣ`.

This connects the executable equality result to the categorical quotient.

---

## 16. Abstract Models

A mathematical model of `Σ` is not a host-language callback table.

It consists of:

- A bicartesian closed category `D`
- Chosen bicartesian-closed structure in `D`
- An interpretation of the signature generators

The semantics of a core morphism is the induced functorial interpretation.

This definition remains independent of:

- Rust
- Dynamic runtime values
- `Any`
- Closures
- Memory layout
- Execution strategy

---

## 17. Runtime Interpreter as One Model Adapter

The Rust interpreter constructs one executable target category of runtime values and total host functions, subject to an explicit trust boundary.

Its implementation choices do not define abstract semantics.

The runtime adapter must be shown to implement the abstract interpretation equations for every trusted core constructor.

The totality and purity of arbitrary host generators remain assumptions unless separately verified.

---

## 18. Rust Correspondence

The formal development must relate Lean syntax to the shipped Rust structures.

Required correspondence includes:

- Signature identities
- Resolved objects
- Checked morphisms
- Source and target indices
- Generator identities
- Equality inputs
- Equality outputs

The preferred direction is a machine-checked refinement path using verification-friendly Rust and Aeneas or another suitable tool.

If that path is replaced, the replacement must still establish a machine-checked correspondence between the executable result and the verified decision procedure.

---

## 19. Trusted Base

The project must explicitly document the trusted base, including:

- Lean kernel
- Rust compiler assumptions
- Translation or extraction tooling
- Aeneas or replacement tooling
- Runtime host assumptions
- Unsafe code, if any
- External libraries used by verified paths

The trusted base should remain as small and visible as practical.

## 21. Completion Standard

Phase 0 may claim to be categorically verified only when:

- The syntactic category exists in Lean.
- Its bicartesian-closed structure is proved.
- Its free universal property is proved.
- Equality is proved terminating, sound, and complete.
- Interpretation is proved to be the unique induced functor.
- The shipped equality implementation is connected to the verified procedure.
- Remaining assumptions are explicitly documented.
