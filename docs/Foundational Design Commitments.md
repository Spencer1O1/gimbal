**Status:** Locked foundational decisions  
**Purpose:** Record the semantic commitments that guide the specification, metatheory, implementation, and future extensions.

These commitments should not be reopened casually while designing syntax or implementation details.

---

## 1. The Pure Core Is Total

A pure morphism:

```text
f : A ⟶ B
```

promises that every valid `A` produces a valid `B`.

A pure morphism cannot secretly:

- Fail
- Panic
- Throw
- Diverge
- Perform I/O
- Read time
- Use randomness
- Mutate external state
- Produce an invalid result

Failure, nontermination, and effects must be explicit.

All generating morphisms admitted into a pure Phase 0 model must be total and pure.

A host implementation that violates this promise is a trusted-model fault.

---

## 2. The Phase 0 Core Is Bicartesian Closed

The foundational pure category contains chosen:

```text
Unit
Never
A × B
A + B
A ⇒ B
```

These represent:

- A terminal object
- An initial object
- Binary products
- Binary coproducts
- Exponential objects

This structure is the semantic basis for:

- Closed values
- Discarding
- Impossible states
- Tuples
- Records
- Variants
- Results
- Pattern elimination
- First-class functions
- Currying
- Evaluation

The Phase 0 core is a variable-free presentation of a bicartesian closed category generated by a supplied signature.

---

## 3. Phase 0 Presents the Free Bicartesian Closed Category

For each signature `Σ`, checked morphisms modulo definitional equality form a category `CΣ`.

The central universal property is:

> `CΣ` is the free bicartesian closed category generated by `Σ`.

For any bicartesian closed category `D` and any interpretation of the base objects and generators of `Σ` in `D`, there exists a unique bicartesian-closed structure-preserving functor:

```text
⟦-⟧ : CΣ → D
```

extending that interpretation.

This theorem must be machine-checked in Lean 4.

The free-category theorem is part of Phase 0 completion.

---

## 4. Morphisms Are the Single Phase 0 Semantic Foundation

The core does not maintain separate foundational systems for values and functions.

Everything in the pure kernel denotes a morphism.

A closed value of `A` is:

```text
Unit ⟶ A
```

A first-class function value is:

```text
Unit ⟶ (A ⇒ B)
```

An ordinary transformation is:

```text
A ⟶ B
```

Packaging a morphism as a first-class function value arises through currying.

Applying a function value arises through evaluation.

Literal and value-oriented syntax may be added later, but it must elaborate into this morphism foundation.

Future effectful computations and resource-sensitive values may inhabit additional connected semantic categories.

They must not be forced into the pure morphism judgment dishonestly.

---

## 5. Phase 0 Is Parameterized by a Signature

The kernel does not permanently hardcode data objects such as `Nat`, `Int`, or `Text`.

Its object grammar is:

```text
A ::= Base(id)
    | Unit
    | Never
    | A × B
    | A + B
    | A ⇒ B
```

A signature supplies:

- Opaque base-object identities
- Typed atomic generating morphisms

The kernel assumes no domain-specific equations between generators.

A temporary arithmetic model may be used for testing.

Mathematical natural numbers become categorical recursive data through controlled initial-algebra constructions.

---

## 6. Core Object Equality Is Structural

Transparent aliases are elaborated away before core checking.

Two core objects are definitionally equal only when they have the same structure and resolved base identities.

The following are not definitionally equal:

```text
(A × B) × C
A × (B × C)

A × B
B × A

A × Unit
A

A + Never
A
```

They may be connected by canonical isomorphisms.

Association, swapping, unit removal, initial-object removal, distribution, and similar transformations are explicit morphisms.

Core products and coproducts are ordered.

---

## 7. The Core Uses Chosen Bicartesian-Closed Structure

Products, coproducts, terminal objects, initial objects, and exponentials are unique only up to canonical isomorphism in an abstract category.

The Phase 0 syntax uses selected representatives and selected introduction and elimination morphisms.

Structural laws are stated relative to these choices.

Phase 0 abstract models must preserve the chosen structure strictly or through a formally specified coherent preservation structure.

The initial Phase 0 metatheory uses strict preservation to keep the free-category theorem precise and implementation-independent.

More general strong structure-preserving interpretations may be added later.

---

## 8. Aliases and Nominal Objects Are Different

A transparent alias introduces no new core object:

```text
alias Bool = Unit + Unit
```

`Bool` and `Unit + Unit` elaborate into the same core object.

A nominal domain type introduces a distinct object even if it shares a runtime representation with another type.

Conceptually:

```text
object UserId from Nat
```

must not make `UserId` definitionally equal to `Nat`.

Aliases and nominal declarations are source-language features.

The Phase 0 kernel contains only resolved base objects and categorical constructors.

---

## 9. `Bool` Is Derived

`Bool` is a transparent standard alias:

```text
alias Bool = Unit + Unit
```

Its values are:

```text
false : Unit ⟶ Bool
false = left[Unit, Unit]

true : Unit ⟶ Bool
true = right[Unit, Unit]
```

Boolean branching is coproduct elimination.

A backend may use an optimized machine representation without making `Bool` semantically primitive.

---

## 10. Every Morphism Has One Source and One Target

Every core morphism has the form:

```text
f : A ⟶ B
```

Multiple inputs are products:

```text
f : A × B ⟶ C
```

Multiple outputs are products:

```text
g : A ⟶ B × C
```

Multi-argument syntax is elaboration.

---

## 11. Phase 0 Morphism Constructors Are Minimal

Primitive constructors are:

```text
id
composition
discard
absurd
first
second
pair
left
right
case
curry
eval
signature generators
```

Composition is a primitive IR constructor.

The following are derived:

- Swapping
- Reassociation
- Unit and initial-object isomorphisms
- Distribution
- `uncurry`
- Ordinary application syntax
- Boolean operations
- Tuple syntax
- Record syntax
- Pattern matching

Derived does not imply inefficient.

Optimizations must preserve the derived categorical meaning.

---

## 12. Phase 0 Is Variable-Free

The semantic kernel has no:

- Variables
- Local bindings
- Parameters
- Substitution
- Lambdas
- Pattern-bound names
- Name resolution

Inputs are accessed through categorical structure.

Phase 1 introduces variables and expression syntax that elaborate into variable-free terms.

---

## 13. Phase 0 Polymorphism Is Metalevel Only

Core constructors are object-indexed families:

```text
id[A]
discard[A]
first[A, B]
eval[A, B]
```

Phase 0 does not contain first-class universal quantification.

Early source-language generic definitions may be implemented as metalevel schemas or monomorphization.

Genuine parametric polymorphism is not merely syntactic sugar for the monomorphic Phase 0 category.

It requires a separately designed categorical semantics.

---

## 14. Pure Recursive Data Uses Controlled Initial Algebras

The language does not admit arbitrary recursive type equations merely because they can be written as:

```text
μX. F[X]
```

Initial inductive data must arise from approved functors whose action is established and whose recursive occurrences satisfy the required positivity restrictions.

Initially, this means strictly positive polynomial functors.

Conceptually:

```text
NatF[X] = Unit + X
Nat     = μX. NatF[X]
```

Pure recursion proceeds through structure such as:

- Catamorphisms
- Structural recursion
- Bounded iteration
- Approved recursion schemes

Unrestricted recursion produces an explicitly potentially nonterminating computation.

Coinductive data requires controlled terminal-coalgebra and productivity semantics.

---

## 15. Definitional, Proven, and Observational Equality Are Distinct

### Definitional equality

Generated by the trusted foundational laws.

It is decidable.

### Proven equality

Established by explicit proof evidence.

It may use domain-specific laws not present in the free category.

### Observational equality

Relative to a selected model or semantics.

Two terms may be observationally equal in one model without being definitionally equal.

### Trusted equality

Accepted through a visible trust boundary when proof is unavailable.

User laws and model-specific equations must not silently enter definitional equality.

A quotient theory with additional equations must be introduced explicitly as a new semantic construction.

---

## 16. Definitional Equality Is the Full Bicartesian-Closed Theory

The trusted equality theory contains:

- Category laws
- Terminal uniqueness
- Initial uniqueness
- Product beta and eta
- Coproduct beta and eta
- Exponential beta and eta
- All consequences under congruence and composition
- Required commuting conversions

A collection of local rewrites is not accepted as a complete procedure unless completeness is proven.

Phase 0 uses a complete saturated-focusing decision procedure.

Its termination, soundness, and completeness must be machine-checked.

---

## 17. Simplification, Equality, and Execution Are Separate

### Simplification

A sound directed transformation useful for:

- Inspection
- Debugging
- Optimization
- Smaller IR

It need not be complete for equality.

### Definitional equality

A verified decision procedure for the free bicartesian closed category.

### Execution

Interpretation in a selected model.

No operation may silently import laws from another.

---

## 18. Mathematical Models Are Categorical

A mathematical model of a signature consists of:

- A bicartesian closed category
- An interpretation of each base object
- An interpretation of each generator
- The required preservation of the chosen structure

Interpretation is the unique functor induced by the free-category theorem.

The Rust `Model` interface is one runtime implementation boundary.

It is not the definition of model semantics.

---

## 19. Runtime Models Are Explicitly Trusted

The Phase 0 interpreter owns the standard runtime representation of:

- Unit
- Products
- Coproducts
- Exponentials

A runtime model owns:

- Payloads for opaque base objects
- Host implementations of generators

The interpreter verifies runtime source and target object tags.

Rust cannot prove that arbitrary host callbacks terminate, remain pure, avoid panic, or avoid hidden effects.

These remain explicit trust assumptions.

Safe language-defined generators should eventually be expressible inside the total language or backed by machine-checked evidence.

---

## 20. Persistent and Resource-Sensitive Values Are Different

The Phase 0 category is cartesian.

Every object therefore supports canonical duplication and discarding.

This is appropriate for persistent pure values.

It is not appropriate for:

- File handles
- Sockets
- Unique memory
- Locks
- Transactions
- Linear capabilities
- Values requiring exactly-once cleanup

Resource-sensitive values must inhabit a noncartesian semantic layer.

The preferred direction is a linear/nonlinear architecture connecting:

- A cartesian category of persistent values
- A symmetric monoidal resource category

through explicit functors, modalities, or an adjunction.

Ownership and resource safety may not be bolted onto ordinary cartesian objects as exceptions to duplication and discarding.

---

## 21. Effects Require a Value/Computation Semantics

Before adding effects, the language must select and formalize:

- The category of values
- The category of computations
- The relationship between them
- Evaluation order
- Function spaces involving computations
- How effects compose and are handled

Algebraic effects alone do not determine the entire value/computation distinction.

Call-by-push-value or another categorical framework may be used, but the choice remains open.

Effects may not be added as untyped runtime actions attached to pure morphisms.

---

## 22. First-Order Algebraic Effects Use Free Constructions

Ordinary first-order algebraic effect signatures should generate free computational structure.

Handlers provide algebraic interpretations.

Conceptually:

```text
effect signature
    ↓
free algebraic construction
    ↓
computational category
    ↓
handler interpretation
```

This mechanism must be derived rather than implemented as unrelated compiler exceptions.

---

## 23. Scoped and Higher-Order Effects Require Principled Extensions

Not every practical effect is represented adequately by first-order algebraic operations.

Examples include:

- Scoped resource management
- Local environment modification
- Masking
- Transactions
- Structured parallel composition
- Scoped cancellation

These require scoped, higher-order, indexed, or otherwise generalized categorical effect structures.

The language must not pretend that every such operation is an ordinary first-order free-monad operation.

---

## 24. User-Defined Categories Have External and Internal Forms

An external category declaration is compiler-level structure containing:

- Objects
- Typed morphisms
- Identity
- Composition
- Law evidence

An internal category is represented as a value or structure inside the language.

Internal categories raise additional requirements:

- Universe levels
- Size distinctions
- Indexed hom families
- Dependent or indexed typing
- Internal equality

The language will not treat arbitrary categories as ordinary values until these questions are resolved.

---

## 25. Ergonomic Syntax Is the Goal, but the Core Comes First

The intended source language should be readable and practical.

Later syntax may include:

- Local bindings
- Pattern matching
- Records
- Named variants
- Lambdas
- Function application
- Effect-oriented notation
- Resource-oriented notation
- Domain-specific syntax

Every convenience must:

1. Elaborate precisely into an existing semantic layer.
2. Introduce no hidden second meaning.
3. Avoid hidden categorical choices.
4. Be inspectable after elaboration.
5. Avoid unnecessary duplicate mechanisms.

Elaboration is structured and type directed.

It is not textual find-and-replace preprocessing.

---

## 26. Every Foundational Feature Requires a Semantic Admission Test

Before a feature enters the language, its design must answer:

1. What categorical structure is being added?
2. What universal property or semantic characterization defines it?
3. What laws does it satisfy?
4. Which laws are definitional, proven, derived, trusted, or model-specific?
5. How does it connect to existing categories?
6. What information does the compiler preserve?
7. What proof obligations arise?
8. What runtime or lowering interpretation is allowed?

If these questions have no precise answers, the feature is not ready.

---

## 27. Phase 0 Metatheory Is Machine-Checked

Lean 4 is the Phase 0 proof language.

Phase 0 must machine-check:

- Formation of the syntactic category
- Category laws
- Terminal universal property
- Initial universal property
- Product universal property
- Coproduct universal property
- Exponential universal property
- The free bicartesian closed category theorem
- Interpretation uniqueness
- Equality termination
- Equality soundness
- Equality completeness
- Correct treatment of opaque generators
- Correctness of the executable equality implementation connection

A paper proof, test suite, or unverified port is insufficient for claims of verified correctness.

## 28. The First Safety Promise Is Precise

The initial language promises:

- Static type safety
- Valid categorical composition
- Total pure morphisms
- Explicit failure
- Explicit nontermination
- Explicit effects
- Exhaustive coproduct elimination
- No hidden universal `null`
- No invalid runtime inhabitants
- Sound simplification
- Correct definitional equality
- Explicit trust boundaries
- A free categorical semantics

Mandatory future goals include:

- Memory safety
- Resource safety
- Lifetime safety
- Concurrency safety
- Data-race prevention
- Safe foreign-function interoperability
- Safe compile-time execution
- Controlled low-level and unsafe programming

Their mechanisms must integrate through explicit categorical structures.
